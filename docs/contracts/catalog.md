# Neuraxis contract catalog

This is the product's contract registry. Each row owns one persisted boundary: its schema, producer and consumer tests, unavailable-data behavior, executable provider and swap test are explicit. `documents` is the committed-document inventory consumed by the template's schema-coverage guard. A `-` means the boundary has no separately committed example or model I/O payload.

## Trust and version rules

Artifact validators verify raw-byte SHA-256, identity, matrix coverage, lineage, outcomes and denominators. A valid schema does not establish that an episode is true or a method is superior. The native API and workspace authority are distinct boundaries; a replayed public trace has no local effect authority. Missing evidence is unavailable, never success by default.

Increment a contract's minor version for compatible optional fields and its major version for changed meaning, required fields, identity semantics or hash rules. Update schema, producer, consumer, tests, lock and readiness in the same change. Never rewrite frozen result indexes to make a new contract appear satisfied.

## Readiness

`data/derived/readiness.json` records the versioned state of every row and SHA-256 of this catalog. Run `python data-pipeline/run.py readiness` to regenerate it and `python scripts/check_readiness.py` to reject drift. `available` means declared code and evidence paths exist; it does not certify owner acceptance, deployment or scientific adequacy.
