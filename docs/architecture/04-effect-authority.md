# 04. Effect authority

An action is executable only when its identifier and version are registered, its argument object passes a strict bounded parser, required resources are present at the observed revision, the operation belongs to the principal's capability set, and the effect budget remains available. A model output or browser event cannot bypass these checks.

The local service uses an operator session token, same-origin validation, fixed capability registrations and size limits. The native broker re-observes resources immediately before dispatch and assigns immutable intent identity. Files, processes and HTTP requests execute through registered effectors; operation receipts record their observed result. User-workspace recipes bind a reviewed preview to file fingerprints and consume that preview once.

The product's supported path rules and leases protect cooperating processes. They are not a kernel sandbox and cannot stop arbitrary external writers or hostile programs running with the same user privileges. Untrusted code requires a separately configured isolation boundary. Uploaded source/configuration files in the Tasks view are parsed as data and never executed.
