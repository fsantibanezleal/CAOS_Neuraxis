# 08. Application and deployment

The shared CAOS shell owns route chrome, theme, language, tabs, document measures and responsive behavior. The Introduction is the executive landing view; scientific sections remain direct routes and the bounded tool surfaces live under `/app`. Focus mode is enabled for the task graph and the investigations stage. Long reading pages remain vertically reachable in document flow.

The static build serves immutable, hash-declared research evidence. The public `/api` surface is disabled. The separate local application composes the authenticated workspace authority and compound native operation API on loopback. Hosted deployment exposes only the bounded task service and its declared registrations, never an arbitrary user workspace or training endpoint.

`deploy/TARGET` names the selected `vps-static+vps-service` class and its reason: the research payload is large and the native API needs a service process. Static packaging includes the exact source revision, version, file sizes and SHA-256 values. `deploy/install_static.py` validates archive paths, limits and digests before an atomic activation; `deploy/install_operations.py` activates an isolated service release. Deployment and live verification are separate release gates.
