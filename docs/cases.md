# Workload and case contracts

The owned suite executes actual disposable software effects. Its initial conditions, fault schedules and goals are designed fixtures. They are neither production traces nor a universal agent benchmark. Every family has six variants: nominal, delayed observation, duplicate event, stale conflict, unavailable dependency and boundary. Each method runs the same held-out seeds and native effect boundary.

| C01 | Workspace document routing | Destination contains expected record and source is absent |

| C09 | Bounded storage pressure | Disposable cache is removed and required report has expected size |
| C10 | Dependency workflow | Extract/transform/report yields the independently computed result |
| C11 | Concurrent file revision | Written state has the expected next revision and value |
| C12 | Agent job collection | Bounded child computations finish and their collected sum is correct |
| C13 | Planner deadline pressure | Scheduled availability is observed and the fixture result is collected |
| C14 | Unsupported planner argument | Rejected action receipt records no execution, valid action subsequently completes |
| C15 | Untrusted tool text | Content checksum matches while the protected file remains unchanged |

| C17 | Novel registered capability | Explicitly registered invocation returns its declared output |

C09 models a configured workspace quota while operating real files; it does not exhaust the host disk. C13's workload availability schedule is a controlled fixture, while model-dependent policies make actual separately measured planner calls. C17 exposes a registered operation under the declared feature schema; it does not by itself prove open-world discovery. Case-specific adversarial inputs are fixture data, never instructions to the host.

## Variants and outcomes

Fault variants alter visible causal conditions or input boundary candidates. Invalid candidates remain in the trace for explanation but cannot acquire authority. The runtime rechecks concrete resource fingerprints immediately before effects. Duplicate or stale observations are handled separately from completed side effects. Outcome truth is verified after execution; model agreement and native admission are not themselves completion.

The standard held-out matrix has 1,200 episodes per method. All failures remain in aggregates. A missing model, blocked external dependency or absent trace is not a measured failure that can be filled with an invented score. Reproduction records identify non-scoreable conditions explicitly.

## External transfer

ToolSandbox and a frozen tau2 revision are separate required transfer lanes with their own upstream task selection, evaluator, user-simulator settings and licensing. Eligible tasks are selected before outcomes are observed. Tasks requiring unavailable third-party services, privileged desktop assets or restricted credentials are listed as excluded with reasons. A subset with a local open model is not represented as an official full-benchmark leaderboard score.
