# Requirements: method names, the SDD ladder and manuscript records

Every requirement names an executable gate. Names used to organize method families remain in design and validation records only.

| ID | Requirement | Gate |
|---|---|---|
| MT-001 | THE SDD's `## Method ladder` SHALL be a table of the columns id, tier, method, acceptance criterion and gate whose tier is `classical`, `sota` or `beyond`; WHEN the table or its tier column is missing (prose, a table without the column, a table inside a code fence), a tier is none of the three, an id is empty or repeated, or a method or criterion is empty or a placeholder, THE script `scripts/check_sdd.py` SHALL fail, saying how to add the column and naming the rule file, for the template as for a product. | `scripts/check_sdd.py` |
| MT-002 | WHEN a product's method ladder has no method of the tier `classical`, `sota` or `beyond`, THE script `scripts/check_sdd.py` SHALL fail naming the missing tier and the rule file. | `scripts/check_sdd.py` |
| MT-003 | WHEN a product's SDD has no section `## Beyond the state of the art`, says `None claimed.` in it (alone or next to a claim), or lists no proposed method `BS-<n>`, THE script `scripts/check_sdd.py` SHALL fail naming the rule file; WHEN a claim has no ladder row of tier `beyond` (a validation protocol alone is not a method beyond the state of the art) or a `beyond` row is no claim of the section, it SHALL fail naming the identifier. | `scripts/check_sdd.py` |
| MT-004 | WHILE the tree holds `.template-source` (the template), THE script `scripts/check_sdd.py` SHALL accept `None claimed.` and a ladder without a `beyond` row or a `sota` row, and it SHALL pass the template's own SDD. | `scripts/check_sdd.py` |
| MT-005 | WHEN a method of tier `sota` in the ladder is named by no level 3 notebook (`caos.methods`) in a language tree, a level 3 notebook names none, `caos.methods` names a method that is no `sota` row, is not a list, sits on a notebook of another level, or differs between the two languages, THE script `scripts/check_notebooks.py` SHALL fail naming the notebook or tree, the method and the rule file; WHEN the SDD has no readable ladder it SHALL leave that table to `scripts/check_sdd.py`. | `scripts/check_notebooks.py` |
| MT-006 | WHEN a product's `product.json` has no `manuscripts` list or its list has no entry of kind `technical-report`, THE script `scripts/check_manuscripts.py` SHALL fail naming the rule file; WHILE the tree holds `.template-source` it SHALL accept an absent or empty list and still validate what is declared. | `scripts/check_manuscripts.py` |
| MT-007 | WHEN a manuscript entry has a `kind` outside `technical-report` and `manuscript`, a `concept_doi` that is not `10.5281/zenodo.<N>`, an empty or placeholder title or version, a technical-report version that is not `X.XX.XXX`, a `covers` that is not a list of `BS-<n>` or (for a manuscript) is empty, a claim the SDD does not list, a repeated concept DOI or an unknown field, THE script `scripts/check_manuscripts.py` SHALL fail naming the entry and the field. | `scripts/check_manuscripts.py` |
| MT-008 | WHEN a technical report's version is ahead of `VERSION`, THE script `scripts/check_manuscripts.py` SHALL fail; WHEN it is run with `--release` and a technical report's version is not `VERSION`, it SHALL fail saying the report is published before or with a release that changes a method, a data source or a result. | `scripts/check_manuscripts.py` |
| MT-009 | THE script `scripts/check_manuscripts.py` SHALL read nothing from the network unless run with `--zenodo`, and under `--zenodo` it SHALL fail a concept DOI with no Zenodo record, a record of another concept DOI and a latest Zenodo version that is not the declared one. | `scripts/check_manuscripts.py` |
| MT-010 | WHEN a tier name ("state of the art" in any spelling, SOTA, "estado del arte", "classical" or "clásico" with approach, method, model or baseline, "method tiers", a claim id `BS-<n>`) appears in a notebook (its file or folder name; its `caos.title`; its markdown outside References; the comments and text strings of its code cells; its text outputs), a notebook index, a manuscript source (its file or folder name; `.tex`, `.md`, `.txt` outside the bibliography, the text of an `.svg`, the strings of a `.py` figure script), a `product.json` manuscript title, the README outside References or an app string (the values of `content/**/*.json`, the strings and JSX text of `frontend/src`), or the bare words "classical", "clásico" or "tier" appear in a title or a heading there, THE script `scripts/check_internal_names.py` SHALL fail naming the file, the place, the words and the rule (CAOS_MANAGE `conventions/method-tiers-and-manuscripts.md` section 0). | `scripts/check_internal_names.py` |
| MT-011 | THE script `scripts/check_internal_names.py` SHALL pass a product that names its methods: a cited title in References or in the bibliography, a lowercase key string (`"sota"`), a fenced block, a code comment or a test file of the app, the SDD and `docs/`, and a line marked `internal-name-ok`; and it SHALL pass the template. | `scripts/check_internal_names.py` |
