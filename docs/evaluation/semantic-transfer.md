# Semantic controller evaluation

The semantic study complements the saturated core benchmark without rewriting it. It compares all twelve frozen controllers on eight compositional families (D01-D08), two conditions and eight held-out seeds (82000-82007): 128 episodes per controller, 1,536 total. These outcomes never enter the core denominator.

Every episode requires three dependent transformations of seeded JSON data. At each step, candidate operations share compatible input/output types and numeric known features but have different described capabilities. Opaque identifiers, candidate order and input contents vary by seed; two families also vary the required transformation. All controllers receive the same visible goal, candidate descriptions and observed outcome history. Hidden expected transformations are available only to demonstration diagnostics and independent verification.

Registered native file effects write stage-1.json, stage-2.json and final.json. Verification reads all three files and compares their values to the required transformation chain. An admitted action or effect receipt is insufficient for success. Incorrect effects can be repaired within the twelve-step limit. The browser presents each observed write and the separate final goal check.

## Measured result

The frozen report records M09 at 38/128 and M12 at 18/128. Their paired comparison has two M12 wins, twenty-two losses and 104 ties. These outcomes do not establish an advantage for M12. The separately fitted semantic routing gate never delegates on its thirty-two held-out cases and shows no held-out improvement. Candidate preference accuracy, effect completion and independent task success are different measurements.

The hash-bound report and index are published under data/semantic-transfer; each trace is checked against its declared SHA-256 and identity before display. Benchmark shows all methods and paired outcomes; App Investigations exposes matched traces, contrast cases, capabilities, planner activity and file consequences. Fresh authenticated runs are exported with fresh-local provenance and remain separate.

A useful future controller must earn its claim on disjoint tasks and matched comparators; interface changes do not change the frozen verdict.
