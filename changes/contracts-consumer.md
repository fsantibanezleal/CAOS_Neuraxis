- The frontend types of the committed documents and of the operations API are generated from the contract schemas (`docs/contracts/schemas/`, `api.openapi.json`) with openapi-typescript 7.13.0 into `frontend/src/lib/contract.gen.ts`; `npm run build` runs `gen-contract-types.mjs --check` first, so a schema change without a regeneration stops the build.
- `ArtifactIndex`, `OperationRun`, `OperationSummary`, `OperationNode` and the report types of the evidence views are now aliases of the generated types; the earlier fallback to an episode-index key `runs`, which no document carries, is removed.
- Consumer contract tests: the committed documents and the provider tree are read against the same declared shapes in both directions (`frontend/src/lib/contract.test.ts`), the nine operations routes against `api.openapi.json`, and the readiness states against the catalog (`frontend/src/readiness/readiness.test.ts`).
- Views show the readiness of the rows they consume as one bilingual line inside their existing container, with the text read from `readiness.json`: the four evidence views served by a provider say so, the operations sidebar gives the reason the service is not part of the static site; available views show nothing. `copy-data.mjs` stops the build when the readiness document is missing or unreadable.
